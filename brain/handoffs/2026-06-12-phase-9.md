# Handoff - Fase 9 Platform Approval + External Smoke

## Objetivo

Aplicar staging externo do FlowCore usando free tier/local, sem afetar NexusReserve.

## Feito

- Render CLI autenticado no workspace `My Workspace`.
- Netlify CLI autenticado na conta do PO.
- Aiven CLI autenticado no projeto `portfolio-01`.
- Aiven recusou segundo MySQL free porque a organizacao ja possui o limite de 1 servico MySQL gratuito.
- Foi criado `flowcore-valkey` no Aiven com plano `free-1`.
- Foi criado o banco `flowcore_staging` no MySQL existente `portfolio`.
- Foi criado o usuario MySQL `flowcore_app`.
- `render.yaml` real foi adicionado na raiz e validado com `render blueprints validate render.yaml`.
- Branch `feature/deployment-readiness` foi enviada ao GitHub.
- `main` e `feature/deployment-readiness` foram publicados ate `857fe9e`.
- Blueprint Render foi aplicado no Dashboard e criou `flowcore-api` e `flowcore-reverb`.
- O primeiro build Render falhou por instabilidade do PECL ao instalar `redis`.
- Dockerfile foi corrigido para compilar `phpredis` a partir do tag GitHub `6.2.0`.
- Build local `docker build -f docker/backend.Dockerfile -t flowcore-backend:render-fix .` passou e `php -m` confirmou o modulo `redis`.
- Site Netlify `flowcore-luantrindade` foi criado: `https://flowcore-luantrindade.netlify.app`.
- `render.yaml` recebeu valores nao secretos de API, Reverb, Aiven MySQL e Aiven Valkey.
- Laravel Redis config passou a aceitar `REDIS_SCHEME=tls` para Aiven Valkey.
- Segredos locais de staging foram gerados em `deploy/secrets/flowcore-staging.env.local` e o diretorio foi excluido via `.git/info/exclude`.
- Senhas dedicadas do Aiven foram resetadas para FlowCore: usuario MySQL `flowcore_app` e usuario Valkey `default`.
- Variaveis `FLOWCORE_*` foram configuradas no Netlify no escopo de build.
- Render remoto validou o Docker build corrigido, mas o runtime da API ainda falha por `REVERB_APP_KEY` ausente no Dashboard.
- Apos preencher os segredos tambem no servico `flowcore-api`, API e Reverb ficaram `live`.
- Render recusou `flowcore-horizon` e `flowcore-scheduler` no Blueprint porque `worker` nao esta disponivel no plano atual.
- `render.yaml` de staging gratuito foi ajustado para manter apenas API + Reverb e usar `QUEUE_CONNECTION=sync`.

## Estado Atual

- MySQL FlowCore esta isolado por database/user no servico `portfolio`.
